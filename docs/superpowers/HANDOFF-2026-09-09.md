## 4. Known limitations (deliberate, documented)

- **The hero's SESSION panel is a hand-written transcript, not a recording.** Every line is something the toolkit really prints, but it is authored. It lives in `hero-data.ts` so a real asciinema cast can replace it by touching one module. **Nothing may describe it as captured output until it is.** Recording it needs you, not an agent.
- **No Vue component test harness** (no `jsdom`, no `@vue/test-utils`) — ruled out by the "no new dependencies" constraint. Component behaviour rests on build assertions plus the manual list above. Revisit only as its own scoped change.
- **`theme.css` keeps its own docs type scale** rather than adopting the `--m-t-*` ramp, deviating from spec §1. Ruled deliberate: the ramp governs landing display type and shared utility steps; docs headings are sized for reading. Recorded in the plan's Known limitations.
- **VitePress's line-number / highlight / diff / focus fence decorations are not re-established in the code rail** — unused on `/introduction`, and focus-blur needs `filter: blur()`, which this theme forbids.

## 5. Deferred minors (none blocking; triaged "fine to defer")

- `fonts.test.ts` asserts preload substrings but not that there are exactly two preloads.
- `HeroFrame.vue` `:key` bindings use content strings rather than indices — fragile only if a transcript line ever repeats verbatim.
- `tokens.test.ts` mis-tokenises a literal-first `calc()` such as `calc(2px + var(--m-s-3))` — over-strict, fails safe, no such value exists.
- `theme.css` now has four near-identical per-tag heading blocks where two combined ones used to be (deliberate — the merge was required for the readability test's helper to resolve `h3`/`h4`).
- Untokenised `max-width` / offset literals in `Landing.vue` — the guard covers only `margin`/`padding`/`gap`/`font-size`, matching the spec's own completion check.
- `.VPLocalSearchBox .result .title` uses an undocumented off-ramp `0.92rem`.

Surfaced by the final re-review (all Minor, none blocking):

- **`span.lang` loses `font-weight: 500` in the rail.** VitePress sets it at
  `vp-doc.css:507`; the rail block re-establishes position but not weight, so the language
  label renders at 400 in the rail and 500 in prose. One declaration.
- **`1280` is written twice** — `RAIL_MIN_WIDTH` in JS and the media query literal. A custom
  property cannot reach a media feature value, so the duplication is unavoidable in an SFC,
  but nothing asserts the two agree. That is precisely the class of drift that caused
  Critical 2. A one-line test regexing both out of `CodeRail.vue` would bind them.
- **The rail's decoration gap is unguarded against upstream content.** `/introduction` is
  generated from a README re-cloned on every build, so its fences are not under this repo's
  control. If upstream ever adds a **diff fence**, the `+`/`-` glyphs vanish inside the rail
  — a silent change of *meaning*, not just style, that no test would catch. (Skipping
  focus-blur remains correct: it needs `filter: blur()`, which the theme forbids.)
- **The `scroll-padding-top` rationale recorded in the commit is wrong**, though the rule is
  harmless and a real improvement for URL-opened anchors. See §3 item 5.
